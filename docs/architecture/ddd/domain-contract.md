# 上下文公開契約

公開契約是上下文對其他消費者承諾的業務語意，包括操作、事實、錯誤及演進方式。它可以是程序內 Port、HTTP API 或整合事件；資料庫文件與內部 Entity 不會因可被讀取就自動成為公開契約。本頁是設計指引。

## 契約內容

| 項目 | 設計產出 |
|---|---|
| 擁有者與消費者 | 誰定義詞義、誰依賴、變更由誰審查 |
| 識別與作用域 | ID 的來源、租戶／Repository、引用失效或無權的語意 |
| 操作與事實 | 輸入前提、成功保證、狀態是當下觀察還是提交結果 |
| 資料語意 | 單位、時區、精度、缺值／零值／清除的差異 |
| 一致性與時效 | 哪些資料同時成立、觀察時間、可接受延遲 |
| 錯誤 | 不合法、無權、查無、衝突、不可用、結果未知的可辨識方式 |
| 重送與版本 | 冪等範圍、預期版本、過期資料與重複投遞的結果 |

定義「accepted」是否僅接受處理，不能讓消費者自行推定已生效或已通知。相同狀態名稱在不同上下文可能有不同語意，轉譯責任見[防腐層](anti-corruption-layer.md)。

## 公開與內部模型分離

用例協調公開能力，Domain 決定自身規則，Adapter 映射 DTO 與傳輸錯誤。跨上下文引用使用對方公開識別與契約，不能直接修改其保存文件或共享可變 Entity。同步／非同步的選擇依[上下文整合](bounded-context-integration.md)及[整合模式](context-mapping-patterns.md)決定，不由目錄名稱推定。

## 版本與相容性

1. 列出可能共存的提供方、消費方、儲存格式及事件版本，版本號不能代替語意說明。
2. 對照新舊組合的輸入、輸出與錯誤；新增枚舉、把缺值改成零值、改變排序或縮小可見範圍，都可能破壞既有假設。
3. 依[模型演進](model-evolution.md)安排擴充、遷移、切換與收縮；定義雙方可支援的期限與無法退回的資料界線。
4. 事件須另外處理已排隊的舊訊息、重複與亂序；不能要求所有消費者同時升級。

## 專案入口與驗收

公開 HTTP 以 [OpenAPI 工作流程](../../../api/README.md)與[能力清單](../../../api/contract/capabilities.json)為來源；操作語意連回[業務操作模型](../contracts/business-operations.md)及[領域規格](../../domains/README.md)。程序內 Port 的責任見[出站埠](driven-port.md)。

驗收至少包含提供方與消費方對同一例子的理解、錯誤映射、舊版相容組合、權限失效、重送與結果未知。型別或產生碼一致不能證明業務語意相容；交付時列出未驗證的消費端。
