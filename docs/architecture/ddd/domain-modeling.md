# 領域建模（Domain Modeling）

由場景、語言、決策和反例反覆修正模型。

## 設計時要確認

先畫正常與例外流程，標出規則擁有者、有效時間與一致性要求，再選模型結構。

## 示例

對照接受、撤銷、到期同時發生的例子，確認哪些結果可成立。

## 從訪談得到可被推翻的規則

請提出需求的人與實際操作的人各講一件已發生的案例，依時間排出「誰提出意圖、依哪個事實判斷、結果由誰承認」。可用 EventStorming 將命令、已發生的業務事件與爭議詞貼在同一時間線上。圖上的事件先當作探索用語，待交付需求確立後才決定是否持久化或發布。

例如同一句「已核准」，審核人可能指決定已記錄，員工可能指新班次已可查。請雙方回答「記錄成功但查詢仍顯示舊值，算不算完成？」記下規則擁有者、可接受延遲與反例。若答案衝突，先標記待決策，再回到[上下文映射](context-mapping.md)釐清詞義；不能由程式設計者替業務決定。
