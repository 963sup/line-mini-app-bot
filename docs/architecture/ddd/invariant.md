# 不變條件（Invariant）

Invariant 是模型在約定的一致性邊界內、每次成功操作後都必須維持的規則。應區分物件始終有效的條件、操作的前置條件，以及允許延後完成的跨邊界流程。

## 規則放在哪裡

| 規則 | 責任位置 |
| --- | --- |
| 時間區間起點不得晚於終點 | Value Object 的建立與運算 |
| 已撤銷邀請不得再接受 | Invitation 的合法狀態轉換 |
| 移除後仍至少保留一位 Owner | 決定該規則的 Aggregate 及一致性策略 |
| 只有目前有管理資格者能移除成員 | 用例協調授權與領域政策，並依風險納入交易 |
| 通知最終送達 | 可靠投遞流程的承諾，不是假設資料提交就已成立 |

上述為設計例子，不宣稱 Membership 已實作。前端輸入限制可改善互動，但不能替代後端模型與交易保護。

## 前置條件與併發

邀請尚未到期是接受操作在指定服務端時間的前置條件；時間過去不表示整個既存邀請物件變成無法存在。需要最新外部事實的條件，須記錄來源、版本與有效時間。

兩個請求可能各自檢查成功、合併後違規。必須定義交易讀集合、版本或其他衝突機制，不能只加一個布林驗證函數。

## 設計產出與核對

每條規則列出適用時間點、擁有者、所需事實、拒絕結果與一致性方式。用成功、非法轉換及併發反例檢查規則，實際驗收依既有階段政策。
