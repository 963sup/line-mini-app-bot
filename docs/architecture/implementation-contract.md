# 實作契約與待決策清單

> 狀態：本次基礎雛形採群組定位打卡、1:1 分群查本人紀錄；規則以功能契約為準，不把後續平台規劃當成首版規格。

順序依 [ADR 0002](decisions/0002-baseline.md)、[基礎設施](../development/foundation.md)
與 [基礎出勤](../features/attendance.md)。群組是打卡範圍，MINI App 單次定位為打卡必經步驟；後台、通知、複雜權限及半徑判斷仍屬後續範圍。
目前不新增測試方案、案例或工具；範本中的測試欄位留待後續階段。

## 第一個可實作切片

目前先完成 HTTP／容器／Cloud Run 骨架，再接入資料與首期 LINE 入口。
後續平台切片參考：接收 user/group Webhook、驗簽、持久接收、去重與 source 分流。
目前只有 [最小接入試作](../development/line-prototype.md)，不含持久接收；不新增健康檢查路由。
本切片不執行任意 Postback、不授予群組管理權、不自動 Push；未知事件安全記錄中繼資料並忽略。
這個切片能先開始，不等於完整業務產品。

## 產品決策閘門

本次基礎雛形只依賴 P01、P04、P05、P06 及定位閘門 P08 中與群組定位打卡直接相關的決策。P02 群組 owner、P03 管理員與 P07 圖片屬後續平台能力，**不是目前群組打卡、MINI App 定位或 1:1 查詢的前置條件**；未來要加入管理後台或群組治理時才重新啟用。

| ID | 未決策問題 | 影響／禁止猜測 | 可繼續的獨立工作 |
| --- | --- | --- | --- |
| P01 | 已定為基礎出勤；入口、人員資格與時間歸屬待確認 | 不擴充排班、薪資或補登 | 執行與部署基礎 |
| P02 | 後續：群組 owner 如何驗證、綁定、移交與撤銷 | 不把首次點擊者升權；不影響目前由後端短效請求綁定群組的打卡流程 | 未來群組治理與拒絕式授權介面 |
| P03 | 後續：管理員登入來源與身分 provisioning | 不自動給 LINE 使用者管理權；目前雛形沒有管理員角色 | 未來 RBAC 契約與管理後台 |

每筆決策需：owner、答案、狀態、日期、受影響 API/schema/tests；確認後以 ADR／功能契約落地。
不需要為每個一般技術選擇詢問；只有依賴缺失產品答案的實作保持 blocked。

## 功能契約範本

每個使用案例在 docs/features/ 下建立具名頁面，確定需求才新增。
必填：目標／非目標、actor、觸發來源、輸入欄位與限制、信任邊界、授權、前置條件、狀態轉移、交易讀寫、外部副作用、冪等鍵、錯誤碼、成功／失敗範例、測試命令、驗收、待決策。
每個函數列出所屬檔案、signature、參數可信度、回傳與錯誤、取消與期限，不只列函數名稱。

## 完整實作就緒條件

P01–P07 中本次功能依賴的答案已確認；API、schema、狀態機與測試案例一致；沒有未定義的角色或結果不明分支。
