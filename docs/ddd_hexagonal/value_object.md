# 值物件（Value Object）

Value Object 以內容判等，沒有需要獨立追蹤的生命週期。領域上相等的兩個值可以互換；變更時以新值取代舊值。

## 適用判斷與責任

以需要一起解釋的值封裝語意，例如時間區間必須同時包含起訖及其合法關係。不要只因幾個欄位常一起出現就包成沒有規則的型別。

建立入口驗證值本身的合法性；是否可以用在目前操作中，由模型或用例依上下文判斷。不可變性包含避免暴露可直接修改的 slice、map 或指標；語言的 struct 宣告本身不保證不可變。

內容判等前須定義單位、時區、大小寫及正規化規則，不能任意清洗識別碼。識別碼也可用值物件表達，但被它識別的對象仍可能是 Entity。

## 設計例子

以 ResourceRef 為例，渠道、資源種類與 ID 三者按各自的識別規則相等時，兩個引用即相等。建構時可驗證必要欄位和種類代碼的格式；若領域語言定義封閉的種類集合，也可驗證代碼屬於該集合。同一個合法引用在資源停用後仍然是同一個值。資源是否存在、該種類是否可參與此操作，以及 Actor 能否操作，分別由用例取得外部事實及套用政策判定。

ResourceRef 可識別外部資源，但自身沒有需追蹤的生命週期，因此按值建模。這個例子只定義引用的語意，沒有決定該值所在的 Go 檔案或 Aggregate。
