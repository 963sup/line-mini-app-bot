# features 工作指引

## 用途與範圍

保存各業務領域的行為、權限與驗收規格。

## 架構與責任邊界

領域文件維護產品規則，公開的請求與回應由 OpenAPI 契約定義。

## 職責與邊界

出勤、工時計算、天氣與摘要等跨模組功能流程及業務規則。
同一功能的前端、API、後端規則集中描述；實作位置以連結指向模組，不複製多份規格。區分已實作、待驗收與未來規劃。

## 維護與驗證

先讀 [本目錄索引](README.md) 與 [文件總索引](../README.md)。索引更新依[文件維護指引](../AGENTS.md#主題子目錄)。
純文件修改驗證本機路徑、標題錨點及 `git diff --check`；設定變更另依父層規定檢查。不把未執行的應用測試或外部驗收宣稱為通過。

新增或修改功能文件時，使用 [操作契約範本](../architecture/contracts/business-operations.md#功能操作契約範本)，區分既有證據、目標行為與待確認規則，不擅自改變產品範圍。

[現行實作圖索引](../diagrams.md#現行實作) · [未來設計圖](../diagrams.md#未來設計)。

在對應功能文件回答六個問題：誰操作、操作什麼、做什麼、有沒有權限、符合哪些業務規則、成功後改變或回傳什麼；補充 Context、Authority、Decision 與依風險需要的 Event／Audit。
區分系統允許／拒絕與業務核准／駁回；Merge 僅於採納提案時使用。

業務模型與契約名稱依[命名規範](../standards/naming.md#業務實體集合與-api-命名)。
