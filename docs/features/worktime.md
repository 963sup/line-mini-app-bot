# 工時計算第一階段

`backend/internal/attendance/worktime` 是不依賴 LINE、Firestore 或薪資規則的純函數模組。

- BuildIntervals：依時間排序事件、按事件 ID 去重、配對上下班與休息事件。
  衝突事件及不合法順序會列出異常，相關輸入不作已確認或暫估工時計算。
- Calculate：接受班次與查詢起訖，分開計算出勤時數、已確認淨工時與含已確認的暫估合計；扣除經確認休息，合併重疊區間，
  只計算報表範圍內的時間。保留 duration 精度，總計最後才換算整分鐘。
- 計算結果包含規則版本、有效區間、待確認筆數與原因，沒有正常／加班分類。

## 操作

在群組開啟「打卡」選單，使用「休息開始」「休息結束」記錄休息，
下班前點「確認本班休息紀錄」。每次操作沿用本人驗證與定位確認頁。
確認代表目前休息紀錄完整；未記休息時代表確認本班沒有可扣除的休息。
新休息操作會取消確認狀態。休息未結束仍允許記錄下班，保留異常不猜測休息時間。

舊班次沒有休息確認證據時仍標示待確認；上下班完整可按出勤時間暫估，不能將暫估視為已確認沒有休息，也不自動扣一小時。
歷史班次可從操作頁提出更正，須由授權審核者核准；不可直接覆寫原始紀錄。
一天可以有多個完成的班次；每次下班後重新上班產生新班次。

## 儲存與報表

原 attendance 文件仍為班次讀取模型，新增休息區間及確認狀態。
每個新操作另在使用者 attendanceRawEvents 保存原始事件、來源、時間、
班次與結果，和事件收據、班次在同一交易提交。既有去重收據阻止重送重複寫入。
既有舊紀錄保留原樣，不虛構舊事件。

月查詢包含與月份重疊的班次，計算時裁切為臺灣時間月初至下月初，
不把跨月整班時間全部算到上班月份。相同工作區間只累計一次並回報重疊異常。
月卡與 Web 顯示暫估合計（包含已確認工時）、出勤時數、休息待確認與無法計算筆數，正常工時／加班待認定。

尚未包含：排班日別、週工時規則、
加班認定、薪資計算、保留期限與匯出管理。本階段不代表勞基法完整驗收。
Firestore 交易仍須使用 emulator／真實測試環境驗證；單元測試不是外部整合證據。

## 共用狀態規則與事件重建

ApplyEvent(State, Event) 是即時交易與 BuildIntervals 的共同規則，
包含結果代碼、是否接受、班次與休息狀態。開始或結束新休息會取消先前確認。
拒絕操作保留原始事件，但不參與班次重建。每個已接受事件有班次內序號，
避免同時間事件因查詢順序不同而產生不一致；同一事件 ID 不可有不同內容。

新建 schemaVersion 3 班次以原始事件重建後供月報計算；舊版維持原有班次讀取，
不虛構缺失歷史。新班次原始事件數量與投影序號不符或重建異常時，
結果列為待確認，保留重建異常原因，不採用投影中的已確認旗標。
計算結果與班次包含來源事件 ID；規則版本為 worktime-v3。
原始資料目前以查詢時計算；更正透過下列提案與核准流程處理，尚未新增持久化報表快照。

## 事件驗證、更正與共用月報

ValidateEventStream 在重建前檢查契約版本、群組／班次身分、事件 ID 唯一性、
從 1 起連續序號及投影期望事件數。月報只讀本月相關班次的完整原始事件流，
避免為一次月查詢讀取整個群組的所有歷史事件。班次索引支援相容與最佳化模式，
啟用、回填與分頁條件見 [出勤查詢](attendance-queries.md)。
CalculateMonthlyAttendance 統一回傳紀錄、計算、事件與更正 ID，供聊天及 API 共用。

新增 API 均使用現有 LINE ID token 認證：

- GET /api/v1/attendance/monthly?group=群組ID&month=YYYY-MM：只讀登入者本人的月報，包含班次 ID、revision 與 eventSequence。
- POST /api/v1/attendance/corrections：JSON 提交 groupId、recordId、expectedRevision、expectedEventSequence、reason、start、end、breaks、restConfirmed。時間使用帶時區的 RFC3339；休息區間使用 Start／End。只能對本人已有班次提案，不直接更動紀錄。
- POST /api/v1/attendance/corrections/{id}/approve：核准提案，僅授權審核者可用且不可自審。

審核權限由受信任管理者預先配置 channels/{channel}/attendanceReviewers/{員工雜湊鍵}
中的 groups 字串陣列；LINE 群組身分不自動授權。沒有配置時任何人均無法核准。
核准交易重新檢查事件序號與更正版本，防止提出後又打卡或其他更正被覆蓋。
核准後保存不可變的提案、修改前後內容、審核者與時間；不覆寫原始事件。
如果補齊尚未下班的班次，交易同時清除該班次的活動指標。
已核准更正的投影用於月報，來源包含 correction ID；重送核准不會再新增版本。
已提供基礎更正表單與按申請編號審核的操作頁；尚無審核列表或新增完全缺失班次的功能。

## 最小結果閉環

GET /api/v1/attendance/corrections/{id} 只允許提案本人查詢。
回傳 pending（待審）、approved（已核准）、stale（原紀錄已變動，需重新提案）。
已核准申請即使之後有其他更正，仍保留已核准的歷史狀態；目前紀錄以月報為準。

月報讀取最新核准的 before／proposal／after 稽核內容，重算本次更正並比對目前紀錄。
稽核缺失、提案歸屬錯誤或內容不符時，該紀錄列為異常，不計入已確認或暫估工時。
這個檢查同時涵蓋舊版班次的更正。僅驗證最新一次核准，不新增完整歷史鏈遍歷。

## 基礎操作頁

開啟 `/miniapp/history` 查本人月紀錄，由班次連結進入 `/miniapp/correction` 提出更正並查詢結果；
授權審核者在 `/miniapp/review` 依申請編號讀取並核准。時間以臺灣時間解讀。
沒有多級簽核、通知或待審列表；詳見 [操作與重試契約](attendance-queries.md)。

Firestore 閉環測試：設定僅供本地測試的 FIRESTORE_EMULATOR_HOST 後，
執行 go test ./internal/attendance/firestore -run TestAttendanceCorrectionRoundTrip -v。
測試建立獨立 channel，覆蓋提案、他人查詢拒絕、自審拒絕、重複核准、
月報更新與損壞證據拒絕。未設定 emulator 時明確跳過，不能作為整合已通過的證據。

整合驗證以各次交付紀錄為準；需要相容的 Java 與 Firestore emulator。
未啟動 emulator 時，套件測試通過不代表資料庫閉環驗證已通過。

## 休息未確認與暫估工時

上下班完整、時間順序與事件證據有效時，不再因尚未確認休息而將整班隱藏於工時之外。
例如 09:00～18:00，先顯示出勤 540 分鐘、暫估工時 540 分鐘（休息待確認）；
確認休息 60 分鐘後，已確認工時與暫估合計改為 480 分鐘，出勤仍為 540 分鐘。
即使已有休息區間，未確認完整性前也不作最終扣除；暫估不是薪資結算依據。

API Calculation 的舊 Minutes／Duration／Intervals 維持已確認淨工時的意義，新增：

| 欄位 | 意義 |
| --- | --- |
| AttendanceMinutes | 上下班及證據有效的出勤時數，尚未扣休息；休息區間異常仍可保留出勤時數 |
| EstimatedMinutes | 暫估合計：已確認班次扣休息，加上休息未確認完整班次的出勤區間；已包含 Minutes，不可再相加 |
| Unconfirmed | 完整、可暫估但休息待確認的班次數 |
| Uncalculable | 缺上／下班、時間／休息區間異常或事件證據無效，無法計算工時的班次數 |

Pending 保留待處理總筆數，為 Unconfirmed 加 Uncalculable。rest_unconfirmed 是待確認
原因，不代表該班次沒有暫估工時；實際異常仍在 Issues。新欄位採相容的額外回應欄位，
沒有任意刷新 frozen API baseline。清單／單筆 AttendanceRecord 另提供完整班次的
AttendanceMinutes、EstimatedMinutes、WorktimeStatus（confirmed／estimated／invalid）。

三種時間總計分別合併重疊區間、裁切月份，再累積秒數並向零截斷為整分鐘；不能先逐班
捨去秒數或直接相加已確認／未確認班次。出勤時數本身不代表可支付工時。清單與 LINE
明細顯示完整班次，月摘要只計當月部分，跨月時兩者可能不同。事件重建衝突、投影或
更正證據異常須單獨標記為無效，不能僅透過取消休息確認後當作正常暫估。

這次變更是讀取時計算與顯示，不改既有打卡／確認休息／更正核准流程，也不批次改寫
Firestore 舊班次。重新查詢即可依新規則取得結果；無須為取得暫估數字而提出更正。
