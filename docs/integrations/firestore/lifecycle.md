# 資料生命週期、保存與恢復

資料從建立、修改、失效到清除都需有責任人與可驗收結果。本頁是儲存設計與維運核對指引；未指定全庫統一保存期限、啟用備份或執行正式資料清除。

## 區分業務失效與實體清除

Repository 的 ACTIVE／INACTIVE 表示入口狀態，[Repository 規格](../../domains/repository/README.md)保留離開後資料與重加入識別。不能把停用解讀成可刪除整庫。

每類資料列出失效依據、保存用途、保留期間的決策者、讀取遮蔽、清除範圍及必要稽核。缺少產品或法規決策時保留待確認，不替使用者設定期限。

## TTL 與過期

[firestore.indexes.json](../../../firestore.indexes.json)宣告 Session 的 `expiresAt` TTL；[身分設計](../../architecture/identity/browser-session.md)負責請求時的有效期判定。依[官方 TTL 文件](https://firebase.google.com/docs/firestore/ttl)，TTL 清理非即時，過期文件在清除前仍可能存在，因此授權不能依賴它是否已被背景刪除。

TTL 清理不代表完成整個業務保留政策。收據、稽核、索引投影與子集合是否保留須逐類決定，不能跟著 Session 規則一起套用。

## 刪除及孤兒資料

依[官方刪除文件](https://firebase.google.com/docs/firestore/manage-data/delete-data)，刪除文件不會自動刪除其子集合。設計清除時列出子集合、外部引用、唯一占用、操作收據及衍生投影，決定刪除順序、可重跑進度與中斷後恢復。

正式批次清除應先產出目標範圍與預估筆數、保留例外、試跑結果、停止條件及恢復限制，再依授權執行。不得把文件整理或程式目錄搬遷當成資料刪除授權。

## 備份與恢復決策

需要備份或時間點恢復時，先確認目標專案／資料庫、可接受資料損失時間（RPO）、恢復時間（RTO）、保存期限、成本及還原權限。是否已啟用須讀取實際環境設定；本庫的部署檔案無法證明雲端保護狀態。

恢復演練以隔離環境核對資料可讀性、跨文件關係、唯一綁定、版本、Session 及重送收據的安全性。還原資料可能重新出現已失效資格或已處理操作，須重新核驗或拒絕，不能直接沿用舊授權。恢復完成需有一致性檢查與切換決策，不只確認匯入命令成功。

## 驗收與交付

交付資料分類、保存／失效／清除責任表、孤兒處理、遷移與回復界線、備份狀態證據及演練結果。尚未決定期限、尚未檢查雲端設定或尚未演練恢復時，逐項列為待確認。
