# API 規範

`api/contract/` 的 OpenAPI 是公開 HTTP 契約的唯一權威來源。Go 與 TypeScript 型別應由契約產生，不得手動維護平行 schema。

## 資源與操作

- 公開 API 使用 `/api/v1` 前綴；內部端點與診斷端點使用獨立契約。
- 路徑以資源與具名業務操作表達，不暴露資料庫集合或內部套件。
- 操作契約需定義 Actor、Resource、Action、前置狀態、成功結果與可辨識失敗。
- 列表需定義穩定排序、分頁游標、篩選語意及回傳欄位。

## 輸入與輸出

- 在 HTTP 邊界驗證外部資料，明確區分缺少、`null`、空值與零值。
- 時間使用明定格式與時區；業務日期由對應領域時區解釋。
- 共用錯誤格式為 `error.code` 與安全的 `error.message`；客戶端依穩定 code 處理。
- 回應不得洩漏內部錯誤、憑證、個資或資料庫結構。

## 寫入可靠性

可能重送的寫入必須定義 idempotency key 的範圍、相同鍵不同內容的行為、版本衝突及回應遺失後的查詢或重試方式。HTTP timeout 不代表後端未提交。

## 相容性

優先採向後相容的新增。移除或改變既有欄位、狀態碼、enum 或語意前，先確認所有消費端與遷移窗口。契約、產生碼、adapter、前端與測試必須在同一變更中同步。
