# LINE MINI App UI 設計規格

這份規格供設計、前端與驗收人員共同使用。現場人員常從 LINE 深連結進入單一任務，例如替今天的班次補卡；管理者也會從桌面儀表板切到某個儲存庫查進度。兩者進入畫面後都要能回答三個問題：我在哪裡、正在處理哪一份資料、下一個動作會產生什麼結果。

設計決策沿用[產品與體驗設計原則](design.md)的六項原則。先寫下誰要完成哪件事、如何辨認成功，再選用最少的元件。下表是各入口的**設計與驗收條件**；自動測試、瀏覽器操作與使用者研究的結果應分別記錄。

## 十二個入口

| 入口與使用情境                         | 操作順序與元件組合                                                                                            | 驗收時要觀察的結果                                                           |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 寫日誌：現場人員記錄今天工作           | Field ＋ Native Select 確認施工儲存庫；Questionnaire 依序填寫工作、預計進度等內容                             | 從儲存庫進入時沿用該庫；必填未完成可回到問題處；送出結果不明時沿用原請求     |
| 申請補卡：人員漏打卡                   | 先辨認群組與班次，再用 Field 填時間、原因並確認；以 Item 呈現申請進度                                         | 「新增漏打班次」與「更正既有班次」可辨別；送出後能區分已申請、待審與失敗     |
| 首頁：從 LINE 進入後找常用工作         | Card 內用有圖示和名稱的 Item 直接前往目的地；側欄保留完整入口                                                 | 點整列或按 Enter 都到相同目的地；返回首頁後能繼續選服務                      |
| 儀表板：主管核對某庫、某日的進度       | Field 選儲存庫與工作日期；Chart 比較實際與預計，Collapsible 內的 Table 提供完整數值                           | 更換條件後，圖表、明細與空狀態對應同一範圍；不用滑鼠懸停也能取得數值         |
| 動態：找出或分享一則日誌               | 使用與儀表板一致的篩選方式；以 Card 顯示日誌，Button 開啟或複製連結                                           | 可辨認工作日期與儲存庫；分享後開到同一則；無符合項目與讀取失敗可分辨         |
| 專案：建立、查看個人或組織專案         | 先選擁有者，再以 Item 開啟詳情；新增表單先填標題，再選來源儲存庫                                              | 選取狀態可辨認；可建立無來源專案；「繼續填寫」保留草稿；分頁重試保留前頁     |
| 儲存庫：選定工作範圍，再查庫內資料     | 總覽用 Field ＋ Native Select 選庫；側欄可展開清單；選定後用 Tabs 切換庫內功能                                | 不必先開側欄才能選庫；深連結直接進入原庫；身分或授權變更後不顯示舊資料       |
| 出勤服務：查某月出勤，再決定是否處理   | Tabs 區分紀錄、請假、更正與審核；月份 Field、Table 及 Button Group 分頁                                       | 切月份後紀錄與頁碼一致；從一筆紀錄更正時保有該班次；無資料可換月查閱         |
| 從文件辨識物件：把文件線索轉成可用物件 | 用 Native Select 選目標庫，Field ＋ 檔案 Input 選檔；將候選物件、原文與已知來源位置並列，覆核後以 Button 建立 | 可區分「已辨識」與「已建立」；可修正候選內容；未確認候選不會自行寫入         |
| 物件範本：用可重複的結構建立物件       | 以 Button 選範本，Collapsible 展開階層；用 Button 移除或復原本次工序、Native Select 選目標庫                  | 套用前可辨認版本與本次建立範圍；完成後可前往根物件；尚無範本時有建立入口     |
| PDF 文字擷取：核對檔案中的文字         | Field 提供選檔條件；Button ＋ Spinner 顯示處理；Textarea 與下載按鈕呈現結果                                   | 無檔案不能送出；等待時避免連送；成功後可下載；空文字與處理錯誤各有說明       |
| 定位測試：確認裝置能否取得並驗證位置   | 使用者按 Button 後才請求定位；以 Spinner、Status 與有文字的 Badge 呈現結果                                    | 拒絕權限後仍能再次操作；能分辨本次與上次座標，以及裝置取得與伺服器驗證的結果 |

## 共用互動

- **位置與範圍。** Sidebar 提供快捷入口、服務與工具；Breadcrumb 呈現當前位置並提供回首頁的連結。收合時工具仍可到達。切換到寫日誌或申請補卡時標示該任務；進入更正既有紀錄時使用出勤服務的脈絡。儲存庫、群組、日期與擁有者是資料範圍，應在受影響的內容或提交動作之前顯示。
- **表單與動作。** Field 使用持續可見的標籤。少量固定選項用 Native Select 或 Radio Group；大量選項且使用者知道關鍵字時才採可搜尋的 Combobox。長流程需要分段回看時用 Questionnaire。按鈕描述動作及對象，例如「建立專案」；尚未滿足條件時，在欄位附近指出缺少的輸入。
- **資料狀態。** 初次讀取用帶有名稱的 Spinner；成功且零筆時用 Empty 說明目前範圍與可做的下一步。暫時讀取失敗用 Alert 和就地重試。變更資料則依[業務操作契約](../contracts/business-operations.md)決定能否修改後重送、沿用原請求或先重新查詢。持續影響操作的錯誤要留在畫面上。
- **手機、鍵盤與輔助工具。** 手機使用 Sheet，長頁面可從頂端工具列切換服務；開啟與關閉都要有具名控制。手機按 Escape 或關閉按鈕後，焦點回到開啟側欄的按鈕。桌面側欄支援收合與鍵盤操作。當前位置用文字或可及狀態表達；可點擊列提供單一焦點；對話框與選單關閉後可繼續原任務。標題、選單及卡片需容納長名稱；表格需要橫捲時，捲動範圍限於表格。
- **辨識與文件。** 可核對的原文比聊天外觀更有用。有多個可追溯來源且可定位原文時，可用 Sources 或 Inline Citation；需要使用者批准的工具呼叫才選 Confirmation。PDF 純文字擷取用檔案輸入與結果欄；模型產生的草稿應明示覆核與儲存的分界。

元件候選查[完整元件與 AI Elements 索引](../development/tooling/frontend/shadcn-reference/snapshot/INDEX.md)；元件 API 依 [shadcn/ui Components](https://ui.shadcn.com/docs/components) 和 [AI Elements](https://ui.shadcn.com/docs/ai-elements) 核對。共用實作入口為[頁面外框](../../frontend/miniapp/src/shell/AppFrame.tsx)、[服務導覽](../../frontend/miniapp/src/shell/ServiceSidebar.tsx)、[內容卡片](../../frontend/miniapp/src/shared/PagePanel.tsx)與[讀取回饋](../../frontend/miniapp/src/shared/ReadFeedback.tsx)。

## 驗收與量測

1. **跨頁走查。** 用相同測試身分從首頁與直接連結各進入指定任務。逐一核對 12 個入口的頁名、所選範圍、第一個可執行動作、回到上一層的方法。至少涵蓋一個窄螢幕與一個桌面尺寸，另驗證側欄收合、長文字、鍵盤 Enter／Escape、焦點與整頁水平溢出。
2. **異常與恢復。** 以空資料、延遲、暫時失敗、權限拒絕及結果未確認作為適用情境。驗證錯誤後的操作確實執行正確請求、沒有重複寫入，且不洩露前一次身分的資料。權限、上傳、LINE 回跳與定位實機應另記裝置、環境及結果。
3. **使用者任務。** 給任務目標，不提示元件位置，例如「找出昨天某庫的進度」或「從漏打班次提出申請」。記錄無協助完成數／嘗試數（目標達成率）、找到正確入口所需時間（理解效率）、完成步數與時間（操作效率）、第一次正確及誤操作次數（操作準確性）。記下停頓、回頭和求助的步驟，用來定位認知負荷。
4. **比較與維護。** 用相同任務、裝置條件與資料比較改版前後；分開報告手機、桌面、鍵盤與輔助工具的結果。把跨頁同義動作的不同標籤、重複元件與例外分支列入審查。沒有真人基準時，回報實際走查結果，不把自動測試通過率當作使用者成功率。
