# 重構流程

重構應降低認知或維護成本，同時保留可觀察行為、契約、資料與安全邊界。

## 前置分析

1. 找出所有呼叫者、產生來源、測試、設定與文件。
2. 建立行為基線；效能重構先量測。
3. 分清結構問題與產品行為變更，避免混在同一提交。
4. 確認工作區中不屬於本次的變更。

## 執行

- 優先搬移責任，不建立轉送層掩蓋錯誤邊界。
- 依 Backend → API → Frontend 順序修正錯置規則。
- 更名時同步型別、路由、設定、測試與文件，最後搜尋舊識別字。
- 合併重複前確認它們有相同語意與變更原因。
- 刪除程式前確認無 runtime、生成、反射、設定或維運入口。

## 驗證

重跑基線與受影響測試，檢查公開契約、序列化、資料相容、授權及效能。跨目錄搬移需驗證來源已清空、目的地完整、所有引用更新。若需要兼容層，明定移除條件。
